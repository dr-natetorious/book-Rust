== Chapter 9: Process the feed and update the book at the same time

Your chapter 8 exercise gave you a measured hot path and a reasoned choice to move forward with threads for bounded handoff. The parser still runs in the same execution lane as book mutation, so one stall blocks both. You now split those responsibilities and make ownership transfer explicit.

=== Send and Sync show where data races are impossible

Try to compile this. Read the error before you read the next paragraph.

[source,rust]
----
include::../src/ch09/race_broken.rs[tag=race_broken]
----

[listing]
----
error[E0596]: cannot borrow data in an `Arc` as mutable
  --> src/ch09/race_broken.rs:14:9
	|
14 |         handle.insert(42, 1);
	|         ^^^^^^ cannot borrow as mutable
----

[WARNING]
====
*Channels transfer ownership.* Once you send a value down a channel, only the receiving thread owns it. That is the locking mechanism. If you try to send the same owned value a second time, the compiler will refuse—because it is already owned by the first receiver.
====\n\nThat compiler stop is the chapter's first win: shared ownership does not imply shared mutable access.
