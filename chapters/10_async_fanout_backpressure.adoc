== Handle a live feed without blocking on slow consumers

Your chapter 9 exercise gave you a parser thread and a book thread that pass ownership safely through a channel. That architecture is clean until one downstream consumer slows down and starts dictating the pace for everyone else. This chapter turns one handoff into async fan-out with explicit backpressure accounting.

=== Futures are suspended work, not background threads

Start by building bounded channels for each consumer lane.

[source,rust]
----

----

If futures are new to your Rust mental model, map them to explicit state machines you can pause and resume. The runtime polls readiness; it does not create one thread per future.

Feed plants care less about average consumer speed than about tail latency in one subscriber lane, because a slow risk or logging consumer can still force pressure on the producer queue.

=== Observe backpressure instead of guessing at it

Run the confidence tests and check that `backpressure_events` is non-zero when the slow consumer delay is enabled.

[source,shell]
----
cargo test --test integration_ch10
----

The hard idea here is operational: a bounded queue is not only a memory control, it is a measurement surface. Once you can count pressure events, you can decide whether to drop, shed, or slow ingestion deliberately.

Everything is concurrent and mostly calm until one subscriber blinks. Then the queue remembers exactly who blinked first.
