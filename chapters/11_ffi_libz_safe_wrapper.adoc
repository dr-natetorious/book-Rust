== Chapter 11: Decompress the sample data without leaving Rust

Your chapter 10 exercise gave you async fan-out with measured backpressure, but your input path still assumes someone manually unpacked data before the program started. That manual step breaks repeatability and makes automation brittle. This chapter removes that external dependency by introducing a small, explicit FFI boundary.

=== Start from the practical problem you already have

You have been handling fixture and sample files as if decompression happens elsewhere. Move that boundary into your code so ingestion can run from one command.

=== Unsafe is a permission set, not a style choice

At this stage, one paragraph of domain context is enough: sample market data is commonly distributed compressed, and preprocessing outside your pipeline adds operational drift between development and production. You are not chasing nanoseconds here; you are removing a fragile manual step that changes what data your tests and runs actually see.

[WARNING]
====
*Unsafe does not mean "no rules." It means "rules trusted to you."* Document the contract, state preconditions, and test violations. Miri will find many bugs faster than production users.
====\n\n`unsafe` lets you perform operations the compiler cannot verify, so your job is to state and enforce the safety contract in code shape.
