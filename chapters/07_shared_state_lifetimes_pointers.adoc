== Share live risk state across the platform without copying it

Your risk engine from chapter 6 enforces pre-trade checks, but it still assumes a caller owns the whole state snapshot. That does not hold once feed processing, risk checks, and reporting all need current positions at the same time. Copying state per component is simple and wrong for latency.

=== Three components, one state, conflicting access

Start with the read-only view first.

[source,rust]
----
include::../src/ch07/shared.rs[tag=borrowed_view]
----

This is the first-contact lifetime move in this book: `'a` names how long the borrowed symbol and borrowed position are valid. If you know pointers and references from C++ or Rust-free systems, the bridge is direct. Rust is not inventing a new memory model here; it is making the borrowing contract explicit in the type.

Risk, book updates, and reporting all query the same symbols repeatedly while market data is flowing. That is why this chapter exists: you need shared live state with precise ownership and mutation rules.

`Arc` shares ownership, not mutable access. The failure is useful because it removes an entire class of race-prone design before runtime.

=== Interior mutability moves one check to runtime

`RefCell` defers exclusive-borrow enforcement to runtime, which is why `try_borrow_mut` returns a typed error. `Mutex` defers exclusivity to lock acquisition, which is why poisoning is part of the error surface. The model is still explicit; the location of enforcement moved.

The dry observation for this chapter: by the time lifetimes stop feeling hostile, you realize they were documenting your architecture before you did.
